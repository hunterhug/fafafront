## 2026-09（最新在前）

### 整理前端产品文档（原始需求记录 + 变动记录）

- 前端产品文档（`requirements.md` / `changelog.md` / `pages.md` / `recommendation.md`）要补充、优化，时间必须按降序，部分章节乱要整理。
- **需求记录纪律**：每次原始需求都需要记录，并且按需求提出和实现的时间顺序降序。

### 国际化（i18n，多语言）

- 前端支持国际化（只对静态不变的文字），默认中文，用户可切换英文 / 日文 / 韩文 / 德文 / 法文等，越全的语言列表越好。
- 翻译要准确、信达雅，可参考苹果地区/语言选择页（https://www.apple.com/choose-country-region/），可以简化。

### 单点登录

- 服务端在 docker compose 里开启 `single_login` 单点登录。

### 接口文档命名统一

- 后端接口文档（docsify）里「你加的接口」命名和之前不一致，保持统一；查看 README 最下面部分和整个接口文档，优化。

### 评论作者可点击 + 批量删除站内信 + 取消评论匿名 + 人类文档

- 文章页评论区：除了匿名用户，其他用户可以点击评论者头像和名称进入用户首页。
- 前端没实现的两个功能：① 个人取消评论匿名；② 个人批量删除站内信。
- 服务端 `docs/version_log.md`（发版历史）与 `docs/todo_list.md`（开发计划）是「人类文档」，在服务端 README 关联；并在前端官网「关于社区」里加两个单独页面。
- todo_list 里「有些功能已实现 / 有很多没列出的新功能」，一起更新。

### 错误提示中文化（服务端英文 + 前端映射）

- 新错误码 110013「can only send one message in 12 hours without mutual follow」；界面错误提示有英文，改为中文，全局检查 Go。
- （修正）服务端**保持英文不变**，在前端做中文映射，前端默认展示中文。

### 举报用户（三类对象都支持举报和封禁）

- 增加举报用户功能，和举报文章、评论一样，前台和后台都要做；举报页里可以封禁用户。
- 总结：三类对象（文章 / 评论 / 用户）都要支持举报和封禁。

### 私信限制（非互相关注）

- 如果用户没有互相关注，12 小时内只能给对方发一条消息，再发时错误提示；互相关注则没有限制。

### 评论被评论通知显示回复内容

- 评论被评论的通知里，评论和被评论的内容都要出现。

### 举报优化

- 同一文章/评论 24 小时内只能举报一次（已举报则提示，否则叠加记录，后台可见）。
- 评论违禁只发一条通知，且举报记录要保留。
- 举报原因面板整齐 + 支持自定义举报原因。
- 举报弹窗在长评论下也要正常显示（PC/iPad/iPhone）。

### 移动端个人中心 / 管理后台优化

- 手机上编辑节点、拖拽节点、写文章都很难用，优化移动端，且不能影响 PC 端。

### 节点 / SEO 编辑拆出编辑器

- 编辑文章时，节点和 SEO 改动后保存草稿/发布没生效（它们和保存草稿/发布无关），把它们从编辑器里拆出来、在内容列表里单独编辑。

### 用户搜索 + 文章搜标题

- 加公开搜索用户，只能搜 `nick_name`，模糊；文章搜索只能搜标题，正文不要。

### 拉黑体验（统一跳转 + 蒙版 + 私信拦截）

- 用户被拉黑后，不要频繁弹窗，统一跳到一个「被拉黑」提示界面。
- 其他人点进被拉黑用户首页，不允许看资料，直接大蒙版提示「已被拉黑」。
- 发私信给被拉黑用户，提示「无法发送」+ 红色感叹号。

### 彻底删除（软删 status=4）

- 回收站里的文章允许「彻底删除」，但仍是软删除（用户世界里没有了，管理员世界可见）。
- 之前有个接口做过「彻底删除」，恢复即可；必须自测，做完提交。

### 软删除 + 占位符 + 回复表情

- 删除文章/评论都必须是软删除，不能级联删除他人记录（评论/点赞/通知等都要保留）。
- 他人通知里被删除对象显示占位符「文章被删除」「评论被删除」。
- 管理后台要有过滤器看到被删除的文章和评论。
- 变更记录按时间降序。
- 回复评论也要能加表情。
