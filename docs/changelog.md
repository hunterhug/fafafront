## 2026-09 修复点击评论报「参数有误」（v1.0.21）

- **现象**：在 SEO 文章页（`/u/:name/node/:nodeSeo/:seo?comment=xx`）点击评论，弹出「请求参数有误」。
- **根因**：详情页的「切换文章重载」`watch` 取值函数每次返回**新数组**，Vue 按引用比较，导致**仅改 query 也会误触发**；
  点击评论会把 `?comment=xx` 写进地址栏，watch 于是把 `contentId` 清零，紧接着的评论请求带上了空 `content_id`，
  后端 `ListHomeComment` 校验失败返回 100010（后端日志：`content_id empty`）。
- **修复**：`watch` 改为监听 `route.path`（只在真正换文章时重载，改 query 不再触发）；
  并为 `loadComments` / `handleCommentAnchor` 增加 `contentId` 未就绪时的早退保护，杜绝空 id 请求。
- **自测**：连续点击 4 个引用块，地址栏正确跳转且页面零报错，后端 `content_id empty` 零新增；跨文章切换重载正常。

## 2026-09 修复：列表摘要露出半截图片 URL（v1.0.15）

- 现象：个人主页（`/u/<用户名>`）文章卡片摘要里出现 `<img src="/storage/admin/image/87a001c7da0f459528d1770246c` 这样的半截图片地址，首页、发现页同理。
- 原因：后端列表接口为省流量把正文按 200 字符截断（`core/controllers/home.go` 的 `Contents`），
  正文里的 `<img … style="…">` 恰好被切在标签中间，返回的摘要以**没有闭合 `>` 的半截标签**结尾；
  前端 `stripMarkdown()` 的 `<[^>]+>` 规则要求标签闭合，于是这半截标签被当成普通文本渲染出来。
- 修复（后端）：截断逻辑抽为 `BuildExcerpt()`，若截断后最后一个 `<` 晚于最后一个 `>`，说明尾部是未闭合标签，从该 `<` 起丢弃；并补上单元测试 `core/controllers/home_test.go`。
- 修复（前端）：`stripMarkdown()` 增加截断兜底——未闭合注释、未闭合 HTML 标签、未闭合的
  `![图片](url` / `[链接](url` 一律清掉（HTML 规则要求带属性或是闭合标签，不会误伤 `a<b` 这类普通文本）。

## 2026-09 修复：带尺寸图片的文章打开编辑器报错（v1.0.12）

- 现象：编辑一篇正文里调整过图片大小的文章时，进入编辑器弹出「页面渲染出错：Cannot read properties of null (reading 'length')」。
- 原因：上一版为保留图片尺寸而输出的 HTML `<img>` 是**顶层块**，markdown-it 会原样输出成块级元素，
  wangEditor 解析后得到「不在段落里的图片」，slate 找不到对应 DOM 节点即抛
  `Cannot resolve a DOM node from Slate node`。用变体逐项定位确认：裸 `<img>` 报错，
  同样宽度写成 `![](...)`（渲染为 `<p><img></p>`）或包在 `<p>` 里则正常。
- 修复：图片尺寸改以 `<p><img …></p>` 存储，与 markdown 图片语法结构一致；同时在加载时兼容历史数据——
  单独占一行的 `<img>` 会被自动补上 `<p>` 包裹，无需改数据库即可打开旧文章。

## 2026-09 后端加密改造配套 + 三个线上问题修复（v1.0.5）

- **上传大文件 413**：私信里发图片报 `413 Request Entity Too Large`。私信不带附件，失败发生在前置的
  `POST /api/file/upload`——前端 nginx 从未配置 `client_max_body_size`，沿用默认 1MB，而后端上限是
  32MiB，超过 1MB 的请求被 nginx 用 HTML 错误页挡掉，后端收不到、前端也拿不到结构化错误码。
  现已在 `location /api/` 放开到 40m（留出 multipart 开销，让超限文件进到后端并由后端返回 100102），
  并在响应拦截器里把 HTTP 413 映射成「文件超过大小限制」的中文提示。
- **后端容器重建后全部 502**：nginx 对 `proxy_pass` 里的静态主机名只在配置加载时解析一次并缓存 IP，
  后端容器重建换 IP 后前端仍指向旧地址（旧地址还可能被 Docker 分给别的容器）。
  改用 `upstream + zone + resolve`（nginx ≥1.27.3）配合 Docker 内置 DNS 动态解析，实测后端换 IP 后
  约 6 秒自动恢复，无需重启前端。
- **提示文案显示成代码**：「推荐用户 / 热门用户」旁的问号提示漏写 `v-bind` 冒号，
  `content="t('explore.hotTooltip')"` 被当成静态字符串原样渲染，浏览器里直接显示 `t('explore.hotTooltip')`。
  改为 `:content` 后正常走翻译。
- **会话失效提示更清晰**：区分「未登录」与「登录状态已失效（可能在其他设备登录）」两种情况；
  已经在登录页时不再重复弹窗（后端开启单点登录 `-single_login=true` 时，被其他端顶掉后
  原本会反复提示，看起来像"登不上"）。
- 新增 i18n 文案 `common.sessionEvicted`（10 种语言）。
